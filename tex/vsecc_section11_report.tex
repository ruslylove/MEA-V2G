\subsection*{Measurement Method}
For each reconnect timing:
\begin{enumerate}
  \item The MQTT \texttt{\_ocpp\_up} event is cleared.
  \item A \textbf{Hard Reset} command is issued via the MEA REST API
        (\texttt{POST /EV/remote/reset}).
  \item The start time is recorded immediately after the reset call returns.
  \item The test polls for two parallel reconnect signals:
        \begin{itemize}
          \item MQTT topic \texttt{vsecc/ocpp\_connection\_status = connected}
          \item MEA REST \texttt{POST /EV/cmd/chargepoint/getConfiguration}
                returning HTTP~200
        \end{itemize}
  \item The elapsed time is recorded when either signal is observed.
\end{enumerate}
The timing includes the vSECC boot time, TLS handshake, and OCPP
BootNotification / BootNotification-Accepted exchange.

\section{Reconnect Time Measurements}

\subsection*{Item 11.1 — Single measurement}
A single Hard Reset is issued and the time to reconnect is measured.
The result is classified as:
\begin{itemize}
  \item \textbf{PASS} if reconnect time $<$ 90 s
  \item \textbf{WARN} if reconnect time is 90--180 s (marginal)
  \item \textbf{FAIL} if no reconnect within 180 s
\end{itemize}
The timing captures the full reboot cycle: OS startup, V2G stack initialization,
WebSocket TLS connection to the CSMS, and OCPP BootNotification exchange.

\subsection*{Item 11.2 — Repeated measurements}
The reconnect measurement is repeated 3 times with 5~s between runs.
Individual run timings are shown in the detail column above.
The average, minimum, and maximum times are reported in the detail field.
The item is classified as PASS if the \emph{average} reconnect time $<$
90~s.

\subsection*{Factors affecting reconnect time}
\begin{itemize}
  \item \textbf{Boot time:} Linux kernel + systemd startup on the vSECC hardware.
  \item \textbf{TLS handshake:} Certificate validation and TLS 1.2/1.3 negotiation
        with \texttt{wss://ocpp.measandbox.com:2930}.
  \item \textbf{OCPP boot sequence:} BootNotification + BootNotification\-Accepted +
        initial StatusNotification messages.
  \item \textbf{Network latency:} Round-trip time to the MEA sandbox CSMS in Thailand.
\end{itemize}

\section{Notes}

\subsection*{Detection method}
The test uses a dual detection strategy:
\begin{enumerate}
  \item \textbf{MQTT:} The vSECC publishes \texttt{connected} to
        \texttt{vsecc/ocpp\_connection\_status} when the OCPP WebSocket
        is established.  This is the most precise signal.
  \item \textbf{REST probe:} A \texttt{GetConfiguration} call is made to the MEA
        CSMS every second.  HTTP~200 indicates the CSMS can forward commands to
        the charger, confirming connectivity.
\end{enumerate}
Whichever signal arrives first determines the recorded reconnect time.
